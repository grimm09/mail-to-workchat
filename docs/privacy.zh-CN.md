# 隐私与公开仓库检查清单

[English](privacy.md) | **简体中文**

邮件系统处理的数据通常不适合放入公开 Git 仓库。请将源代码与本地运行数据视为两类独立资产。

## 公开分发边界

只公开可复用的邮件路由、草稿和可选交互代码、中性文档以及虚构示例。独立的公司管理平台项目不包含在此仓库中。
“个人版”指一组可选功能，不是维护者个人安装环境、账号或工作资料的副本。

已有的个人标题关键词库、知识库、业务数据库、私有规则和真实回复模板均不属于分发内容。程序不会自动发现或导入它们。
每位使用者自行提供本地邮箱配置和模板。应用的 SQLite 状态库由各自部署创建，不是随项目附带的关键词库。

## 不得公开的内容

- `.env` 文件、邮箱密码、应用密码、API 密钥、签名密钥或完整 Webhook URL；
- SQLite 状态、通知发件箱文件、日志、崩溃转储或导出的邮箱数据；
- 生成的草稿、待审批提案或私有已批准模板；
- 个人关键词／知识库、业务数据库，以及真实业务规则或模板；
- 真实发件人／收件人地址、主题、邮件 ID、客户 ID、订单 ID 或附件链接；
- 从生产环境复制的截图和接手文档；
- 真实群／会话 ID、应用 ID、用户 ID、机器人凭据或交互事件导出文件；
- 曾包含上述任何内容的旧 Git 历史。

## 每次公开发布前

1. 从仅包含允许公开的源代码和文档的新仓库构建发布内容。
2. 运行测试集，包括隐私回归扫描。
3. 检查 `git status --ignored`，确认运行数据已被忽略。
4. 使用密钥扫描工具检查完整 Git 历史，而不只是工作区文件。
5. 人工检查示例文件；示例必须使用 `example.com` 等保留域名。
6. 如果任何密钥曾被提交，即使重写了历史，也应先轮换密钥再公开。
7. 对照预期的最终工作区版本，核对准确的暂存快照，包括新增文件。旧暂存区不得遗漏后续修复或文档修改。
   不要不加限制地上传整个目录，也不要强制添加被忽略的文件。
8. 首次公开前，确认许可证及维护者认可的公开提交身份。从审查后的最终版本重新构建分发包；
   旧压缩包不会自动包含后来修改的文档或源码。

回归扫描覆盖已跟踪文件和未被忽略的文件，不扫描正常被忽略的本地秘密；如果私有配置被 `git add -f` 强行加入，
仍会被检查并拒绝。没有 Git 元数据时，扫描只检查文档约定的源码／示例目录。两种模式都不等同于完整的密钥扫描、
Git 历史审计，也不代表可以公开整个工作目录。构建后的压缩包应单独检查。Docker 排除规则同样覆盖本地配置与运行数据，
不要替换成不受限制的构建上下文。

## 本地数据保留

`.runtime/state.sqlite3` 保存邮件键、邮箱 ID、UID、规则 ID、时间戳、通知载荷、长度受限的邮件摘要、事项状态、
模板版本和交互审计记录。审计记录只以 SHA-256 衍生标签保存群和用户 ID，但这属于假名化，并不保证匿名。
`.runtime/drafts/` 包含回复内容。请按照组织政策决定保留期限，并妥善保护和备份这些文件。
事件响应缓存可能包含完整的已展示草稿，保存的提取字段也可能包含业务数据；用户 ID 哈希化不代表数据库已经匿名。
隔离记录只包含 UID、位置和原因。

程序目前不提供自动保留期删除。这是有意保留给部署者的决策，因为保留政策取决于各自的法律和业务要求。

## 远端目标

办公群通知会将选定的邮件数据发送到另一个服务。请缩短摘要、收紧规则，只配置同事确实需要的字段。
确认目标工作空间和群成员有权接触相应邮件数据。
将群用户加入白名单，意味着授权其访问该部署的全部事项，而不只是发送到该用户所在群的邮件。
如果这一范围过大，请使用相互独立的部署。
