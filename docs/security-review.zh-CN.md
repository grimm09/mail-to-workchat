# 0.2.1 安全修复与验证记录

[English](security-review.md) | **简体中文**

日期：2026-10-15。版本：0.2.1 Alpha。

本次已修复复现出的权限缓存、邮件解析、草稿一致性、模板更新和连接器问题，完成三轮本地检查。
这是源码审查与离线对抗性回归，不是对真实平台的渗透测试、第三方认证，也不能保证不存在未知漏洞。
以下结果仅对应本仓库所述版本和测试环境；不代表独立公司版、既有个人部署或所有操作系统与平台均已验证。

## 范围与信任边界

- 修改对象仅为这个准备公开分享的项目；不修改原个人生产系统。
- 不连接真实邮箱，不调用真实群 Webhook，不启动真实 Stream 会话，不发送邮件。
- 不创建 GitHub 仓库，不提交或上传代码；项目原有暂存区保持不变。发布前仍需把最终修复纳入待发布版本。
- 每位使用者自行部署。同一实例的获准用户共享该实例所有邮箱的案件、草稿和模板历史；管理员额外拥有忽略与模板修改权限。
- 这里验证的“横向越权”是冒用他人事件、切换身份/群或重用缓存，不代表实现了同一实例内部的群与邮箱隔离。
- 不同数据可见范围必须使用独立配置、应用凭据和运行目录。“个人版”也需要办公平台授予相应应用权限。

## 修复及影响范围

| 问题 | 修复 | 影响与回归重点 |
| --- | --- | --- |
| 未授权身份能触达既有事件响应，事件号未绑定请求 | 先重新鉴权，再校验平台/机器人/群/用户及请求指纹；拒绝分支不返回缓存 | 互动服务、事件表；跨身份/内容重放、管理员撤权 |
| 崩溃后事件永远停在处理中 | 有期限的处理租约；暂时失败可重试，已完成操作复用结果 | 事件表增量迁移；处理中重入、过期恢复 |
| 深层 MIME、HTML 和长空白串可能阻塞后续邮件 | MIME 深度/部件及读取大小限制；逐 UID 隔离；替换易回溯清理逻辑 | 解析、IMAP、断点；异常 UID 后的正常邮件继续处理 |
| 重复 Message-ID 或离线预览覆盖关联草稿 | 提前去重；草稿文件名包含内容摘要 | 邮件编排、草稿；原案件字段及回复保持一致 |
| 首封待审草稿批准后不能使用 | 保存实际提取值与规则指纹；兼容时生成新的 ready 草稿 | 案件表、审批和回复；不从截断正文猜测字段 |
| 并发模板确认覆盖新版本，中断后文件/数据库不一致 | 跨进程写锁、旧版本校验、先记录 applying 意图、幂等恢复；删除危险的旧文件回滚路径 | 模板仓库、变更表；并发确认和文件写入后的中断 |
| 占位符允许格式扩张，字符串 false 被当作真 | 只允许简单命名变量，展开前限长；布尔值严格检查 | 配置、模板、事件；属性/索引/格式宽度/转换被拒绝 |
| 钉钉字段映射与确认逻辑有误 | 修正 senderStaffId 与 SDK message_id；缺失时间/提及信息不默认放行；暂时故障返回失败 ACK | 钉钉连接器；已安装 SDK 0.24.3 的本地适配测试 |
| SDK 日志和默认 HTTP 行为可能泄密或挂起 | 屏蔽 SDK 私密日志内容；自有 HTTP 超时、拒绝重定向、回复目标限制；检查明确成功码 | Stream 建连/会话回复、钉钉/飞书通知；无真实网络请求 |
| 忽略后仍有排队通知，长差异/草稿被截断 | 取消 pending 队列；长草稿要求本机查看；长差异取消提案，不能据截断内容批准 | 案件操作、队列、模板审核；已在途通知不能撤回 |
| 本地正常配置让脱敏检查误报，源码包不完整 | 检查跟踪及未忽略的发布文件；仍拒绝强制加入的私密文件；补充 Docker 排除与源码分发清单 | 隐私测试、打包；示例和虚拟夹具保留，运行数据不纳入 |

兼容性说明：数据库只增加表/字段；没有删除旧数据。已有 ready 草稿保持历史快照，不因模板更新被静默改写。
旧记录没有字段指纹，或批准时修改了匹配/提取规则的，必须使用原邮件在本机重新预览并人工复制。

## 三轮离线验证

三轮由同一审查流程执行，不是三个独立审计机构或三个独立智能体。测试存在重叠，不能把次数相加当作独立用例数。

1. 权限与连接器：`tests.test_interaction`、`tests.test_dingtalk_connector`，17 项通过。
   验证群/用户白名单、管理员限制、事件时效、缓存身份替换、官方回复目标、日志脱敏、超时与失败确认。
2. 恶意输入与故障恢复：`tests.test_security_regressions`、`tests.test_http_transport`，32 项通过。
   验证深层 MIME、达到读取上限、20 万字符畸形 HTML/空白串、模板扩张、多行命令、并发变更、崩溃恢复及错误响应。
   耗时攻击样本放在有 8 秒超时的子进程中，避免测试本身无限等待。
3. 全量兼容与发布面：`python -B -m unittest discover -s tests -q`，91 项通过、无跳过（Windows / Python 3.11 / DingTalk SDK 0.24.3）。
   包含增量数据库迁移、去重、队列、模板、脱敏、数据库 WAL/SHM 旁文件排除及 SDK 测试。
   已构建 wheel，核对其中 33 个源码模块与工作区逐字节一致，并从独立临时安装目录验证导入、CLI 帮助与示例配置检查。
   源码归档包含文档、示例配置和虚拟测试夹具；已经解包运行回归，归档路径检查未发现私密配置或运行数据。

网络相关测试使用伪造输入和替身传输；连接器测试禁止真实 socket 连接。
CI 已配置 Python 3.11/3.12 的核心/钉钉两类任务，但本次没有在 GitHub 执行 CI；不能把本地结果描述为云端或跨平台验证。

复现命令：

```bash
python -B -m unittest tests.test_interaction tests.test_dingtalk_connector -q
python -B -m unittest tests.test_security_regressions tests.test_http_transport -q
python -B -m unittest discover -s tests -q
git diff --check
```

## 死代码、循环与防御代码

- 移除没有调用方的模板包装方法、提案生成的未使用参数，以及扫描结束时重复写断点的分支。
- 常驻轮询与 Stream 维持连接的循环是运行机制，不作为死循环删除；邮件轮询有等待，队列有重试上限，模板锁有超时。
- 错误返回保留在不可信输入、文件/数据库边界及平台回调处；没有用“出错也算成功”掩盖发送失败。
- 不为开源单实例工具增加多租户框架、任意执行聊天命令或复杂自动学习机制。

## 剩余限制与发布前事项

1. 尚未完成真实邮箱、钉钉、飞书或应用权限联调。正式使用前需另行授权，在独立测试邮箱/群确认平台字段、签名、消息长度和会话有效期。
2. 自定义 Python 正则仍在主进程执行，没有硬超时。不良的嵌套/歧义重复可能被邮件内容触发耗时；仅允许可信维护者修改规则，并用长的不匹配输入测试。已修复本项目内置清理逻辑，不宣称任意用户正则都安全。
3. 只支持同一本地状态库的一个邮件扫描/发送进程和可选伴随机器人；不支持多实例抢占、网络文件系统锁或分布式运行。远端已接收但本地未记录时，重试仍可能重复通知；不是 exactly-once。
4. SDK/传递依赖没有做完整在线漏洞数据库扫描。本次不是依赖供应链审计；发布时应在干净环境重新解析依赖并核对安全公告。
5. 脱敏检查是规则扫描，不是完整泄密检测。还需人工检查最终 Git diff、所有拟公开历史和归档；本次项目没有可审查的已提交历史。忽略规则不能保护已经跟踪的秘密。
6. 运行目录内有邮件摘要、字段、模板、草稿及事件回复缓存。摘要化用户 ID 不等于整个数据库匿名化；仍需限制本机访问并自行制定备份/保留策略。
7. 发件人正则仅用于分流，不能证明发件人身份。所有草稿仍应由人核对内容和收件人；项目没有 SMTP 自动发送能力。
8. 仓库公开前配置私密漏洞报告入口，不要把含真实数据的漏洞复现放进公开 issue。参见 [GitHub 私密报告说明](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)。本次未修改任何 GitHub 设置。

## 升级与故障恢复

停止扫描、定时任务及机器人进程，备份完整运行目录与已批准模板目录，再升级。首次初始化执行增量迁移。
不要在进程写入期间只复制 SQLite 主文件；WAL 文件可能仍包含未合并的数据。

解析失败查看 `mail-failures`，记录只包含邮箱/文件夹/UIDVALIDITY/UID/固定原因，不存原始邮件。
达到大小上限的邮件也会被保守隔离，不自动重试；邮件仍留在来源邮箱，可检查后本机预览或修正后作为新 UID 重发。
临时网络错误不会被误当作永久坏邮件跳过。

模板确认中断后重发同一条 `模板确认 <变更编号>`；不要删除 `.writer.lock` 或抢先手动覆盖模板。
该锁由操作系统持有，进程退出会释放，锁文件留在原地是正常状态。回复丢失时先查询状态/历史，再决定下一步。
